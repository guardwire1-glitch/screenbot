             SCREENBOT PRO - STANDALONE VERSION
=======================================================================

HOW TO RUN:
-----------
1. Extract this zip folder (Right-click -> "Extract All...").
2. Double-click "SETUP.bat" and paste your free Gemini API key
   (get one at https://aistudio.google.com/).
   SETUP saves it to %APPDATA%\ScreenBot\config.json - a file that stays
   on YOUR PC - and then runs a self-test to confirm everything works.
3. Double-click "ScreenBot.exe" (or "START_SCREENBOT.bat").
   * NO Python installation is required!
   * Works on any Windows 10/11 machine.
4. A separate notification-area status icon reports that ScreenBot is
   running, with the current language and Auto-Scan state. It stays while
   ScreenBot runs and disappears when ScreenBot exits; it is not a
   60-second popup. Startup and hotkey beeps are controlled by the
   "sound_feedback" setting (on in the built-in defaults; set it to false
   to mute).
   Auto-scan starts automatically only when "auto_scan_enabled" is true
   in your config. Press Ctrl + Alt + \ to start or pause it at any time.

WHERE IS MY API KEY STORED?
---------------------------
ScreenBot resolves the key in this order (first NON-BLANK value wins):
  1. System environment variable  GEMINI_API_KEY / GOOGLE_API_KEY
  2. .env file next to ScreenBot.exe
  3. %APPDATA%\ScreenBot\config.json   <-- SETUP.bat writes here
  4. config.json next to ScreenBot.exe

A blank value never overrides a real one, so a blank template cannot wipe
the key you saved on your own PC.

Do NOT paste your key into the config.json or .env inside a folder you
share. In this working repository both files are gitignored because they
can hold a real key; never commit, zip, or share them while populated.

=======================================================================
RELIABILITY ARCHITECTURE (LIVE-CLASS PATH)
=======================================================================

1. LOCAL PIXEL GATE
   - A local pixel diff runs before every AI call. If the lecture video is
     static (speaking, drinking water, showing a slide without typing),
     ScreenBot skips the cloud call and spends no quota.
   - Pending consensus lines always force a scan even when the frame looks
     static, so a line is never stranded.

2. APPEND-ONLY CONVERGENCE
   - Lines that scroll off-screen are treated as unseen, not deleted.
     Scrolling cannot erase code already delivered.
   - Lines already present in the file are never typed again. Repeated
     frames are idempotent.
   - Destructive rewrites are disabled on the live path; conflicting user
     code is held for review instead of overwritten.

3. TWO DELIVERY MODES
   DIRECT FILE SYNC (zero keystrokes):
     * VS Code, Antigravity, Cursor, Windsurf: press Ctrl + Shift + F in
       the editor. ScreenBot binds the exact active file through the
       ScreenBot Editor Bridge extension and writes its real buffer,
       including unsaved edits.
     * Visual Studio: Ctrl + Shift + F uses the DTE adapter when pywin32
       is installed. Without pywin32 the bind is refused because the
       active path is unknown; set "target_file_path" to use the saved
       file instead. The DTE adapter retries a missing or restarted
       Visual Studio with a short backoff. Its edit replaces only the
       changed line range and is recorded as ONE undo action, so a single
       Ctrl+Z reverts the ScreenBot change without touching breakpoints
       on other lines.
     * JetBrains, Eclipse, NetBeans, SSMS, and other disk-based editors:
       these expose only a filename in their window title, so ScreenBot
       will NOT guess a path. Set "target_file_path" to the exact saved
       file in config.json and enable Direct File Sync. The file is
       written automatically only when ScreenBot can PROVE the editor
       buffer is saved. VS Code/Antigravity titles are trusted; JetBrains,
       Eclipse, NetBeans, SSMS, and Notepad++ do not report saved state
       reliably there, so a change for an open file in those editors is
       queued for review instead. Save the file, accept the review item,
       then reload it in the editor if needed. If no editor is running,
       the file cannot have an unsaved buffer and the write is allowed.
     * Every direct write is hash-checked, saved-state-gated for disk
       editors, syntax-gated, and diagnostics-gated (where diagnostics
       exist). The bot never types into Teams, YouTube, or a meeting chat
       in this mode.
     * The editor may or may not auto-reload a file changed on disk.
       Reload it if prompted. Indentation comes from the merged document;
       optional formatting is off by default.
   SMART CARET MODE (set "direct_file_sync": false in config.json):
     * Pastes at your cursor only when the exact editor window captured at
       snapshot time still has focus and is not a browser/meeting window.
     * The payload is dedented and ends with a newline.
     * Ctrl + Alt + Z in this mode restores ScreenBot's internal master
       only; use the editor's own undo for typed text.

4. TWO-FRAME STABILITY + TWO-READ CONFIRMATION
   - Each scan compares two frames ~350 ms apart. If the video is
     buffering, scrolling, or mid-keyframe, the frame is discarded before
     the AI call.
   - A brand-new line must be seen on two consecutive scans before it is
     written, so a one-off OCR hallucination cannot corrupt your file.
   - ACTIVE-LINE HOLD: the bottom-most line (the one still being typed)
     waits "active_line_hold_frames" extra scans (default 2). An
     incomplete line such as "int total =" or "if (ready)" is held until
     it is finished or another line appears below it. Manual sync
     bypasses this hold.
   - At the default 5 s scan interval, expect roughly 10-15 s for that
     last line, plus capture and AI time; lines above it arrive sooner.
     Press Ctrl + \ (or Ctrl + 3) to sync the current frame immediately.
   - A vision answer older than "max_frame_age_seconds" (default 12 s) is
     discarded instead of applying outdated code.

5. EDITOR-SAFE SYNTAX / DIAGNOSTICS GATE
   - The full proposed document is syntax-checked (tree-sitter for
     C#/Java/Python, delimiter scanner otherwise).
   - A change that adds parser errors is queued, not applied.
   - If the editor's error count increases after an apply, the change is
     rolled back and queued for review.
   - Re-adding a line the user deliberately deleted is refused and queued.
   - Lecturer edits/replacements detected by the merge are never
     auto-applied; they are queued for review.
   - An identical held change is queued once, not once per scan, and a
     dismissed proposal is not queued again.
   - For disk-based editors, a saved state that cannot be verified counts
     as "do not write" and is queued instead.

6. STUCK-KEY PROTECTION (NO REBOOT REQUIRED)
   - Releases Ctrl/Shift/Alt/Win automatically at startup, after every
     hotkey, and on exit, so a swallowed key-up cannot turn later clicks
     into Ctrl+clicks (new links/windows) or Ctrl+drags (duplicates).
   - A watchdog also catches a modifier held for more than 25 seconds.
   - Emergency recovery: fix_stuck_keys.bat (works without ScreenBot).

HOTKEYS & CONTROLS:
=======================================================================
ANSWER HOTKEYS:
- Ctrl + 0              : DIRECT ANSWER (concise, copied to clipboard)
- Ctrl + 9              : EXPLAINED ANSWER (answer + short rationale)
- Ctrl + 8              : PARAPHRASE (rewrite in your own words)
- Ctrl + 2              : EXAM HIGHLIGHT & SOLVE
                          (also Ctrl+Shift+V, Ctrl+Alt+V, Ctrl+7)

LIVE CODE FOLLOWER HOTKEYS:
- Ctrl + \ (or Ctrl + 3): SYNC NEW LECTURE LINES NOW
- Ctrl + Shift + F      : BIND the exact active file and sync
                          (VS Code family / Visual Studio; suppressed so
                          the editor's Find-in-Files does not open)
- Ctrl + Shift + \      : FORCE FULL RE-SYNC
- Ctrl + Alt + \        : PAUSE / RESUME AUTO-SCAN
- Ctrl + 4              : AI LECTURE NOTE-TAKER (Slides to Cornell notes)

OTHER:
- ESC / Ctrl + Shift + X: EMERGENCY STOP (halts typing/action)
- Ctrl + Alt + Z        : UNDO LAST CODE EDIT (see limits above)
- Ctrl + Shift + Q      : EXIT SCREENBOT (also Ctrl + Alt + Esc)

LIVE CODE FOLLOWER LANGUAGES:
- "subject": "auto" lets the extractor detect the language from the code
  on screen. The built-in default is "java"; set "auto" explicitly (or
  pin a language) in config.json.
- Supported: Java, C, C++, C#, Python, JavaScript/TypeScript, PHP, Ruby,
  Go, Rust, Kotlin, Swift, SQL, HTML/CSS, and shell scripts.
- The tray menu -> Subject Preset can pin Java SE/OOP, Advanced Java, C,
  SQL, or Web. For any other supported language, set "subject" in
  config.json to one of the names above.
- ScreenBot never translates code: it transcribes the language shown.

The highlight-and-solve typing speed defaults to "typing_wpm": 38 and is
configurable in config.json.

=======================================================================
EDITOR BRIDGE (OPTIONAL, RECOMMENDED FOR VS CODE FAMILY)
=======================================================================
ScreenBot starts a localhost-only bridge while it runs and writes
%APPDATA%\ScreenBot\bridge.json (token-protected). Every request must send
the token in the X-ScreenBot-Token header; a token in the URL is rejected.
The optional extension in ide_extension/vscode supplies the exact buffer,
diagnostics, hash-checked applies, and the pending-change review UI to
VS Code, Antigravity, Cursor, and Windsurf.

Install it by copying ide_extension/vscode to:
  %USERPROFILE%\.vscode\extensions\screenbot.screenbot-editor-bridge-1.0.0
  (%USERPROFILE%\.antigravity\extensions\... for Antigravity)
then restart the editor. The status bar shows "ScreenBot: bridge
connected". Command palette commands:
  - ScreenBot: Show Bridge Status
  - ScreenBot: Review Pending Code Changes

Without the extension, VS Code-family editors fall back to the disk
adapter (saved files only) if used via target_file_path. The extension's
own test suite runs with "npm test" in ide_extension/vscode; no editor is
required.

TROUBLESHOOTING:
=======================================================================
- "GEMINI_API_KEY is not set." -> Run check_status.bat to see which tier
  the key came from. If none, run SETUP.bat and paste your key.
- No tray icon -> It may be in the overflow area next to the clock.
  Run check_status.bat.
- Editor extension says "waiting for app" -> Start ScreenBot first; the
  discovery file exists only while it runs. Restart the editor after
  installing the extension.
- Hotkey does nothing -> Another app owns that combination. Change
  "hotkey" in config.json and restart.
- Editor never changes -> Direct sync needs a bound target: Ctrl+Shift+F
  in VS Code/Visual Studio, or "target_file_path" in config.json for
  JetBrains/Eclipse/NetBeans/SSMS. For those editors the saved state
  cannot be verified from the window title, so a change for an open file
  is queued instead of auto-written; save the file and accept the review
  item. If no editor is running, the write is allowed. Reload the file in
  the editor after accepting. Visual Studio reconnects automatically if
  it was started or restarted after ScreenBot.
- Code lands in chat/wrong app -> Fixed: a successful file write always
  skips caret injection, and caret mode aborts unless the original editor
  window still has focus and is not a browser/meeting window.
- A line is skipped or delayed -> By design: unstable frames are skipped,
  a new line must appear on two consecutive scans, and the bottom line is
  held longer while it is being typed (an incomplete line is held until
  it is finished). Press Ctrl + \ to bypass the hold and sync now.
- "A change was held for review" -> VS Code family: run
  "ScreenBot: Review Pending Code Changes" (it can also resolve an item
  for another editor by path). Reasons include an unsaved buffer, saved
  state that could not be verified, a hash conflict, a line you removed,
  a syntax failure, or worsening diagnostics. The same change is queued
  once, not every scan. For disk-based editors, save/reload after
  accepting. The item is stored under session_data/ until resolved.
- Undo refused -> The bound file contains newer user edits, so ScreenBot
  left them untouched. In caret mode undo only restores the internal
  master.
- Clicks open links/new windows or duplicate items -> A stuck Ctrl key.
  Run fix_stuck_keys.bat. No reboot needed. ScreenBot also releases
  modifiers on startup, after every hotkey, on exit, and after 25s.
- Auto-scan pauses / log says 429 -> Gemini free-tier rate limit.
  ScreenBot pauses AI calls for 90s by default
  ("quota_cooldown_seconds", minimum 15), then resumes.
- No beep on startup -> Set "sound_feedback": true in config.json if you
  want cue beeps. The separate status icon is not a timed popup.
- Wrong language written -> Set "subject": "auto" in config.json, or pick
  a language in tray -> Subject Preset. The follower never translates.
- "running directly from ZIP" -> Extract the archive first.
